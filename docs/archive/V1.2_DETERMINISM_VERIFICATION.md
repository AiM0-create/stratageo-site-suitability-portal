## Known remaining non-determinism sources

| Source | Remaining? | Notes |
|---|---|---|
| Study area place names | Partial | LLM still enumerates localities; different runs may pick slightly different sets. The polygon and hex count may vary. Determinism of locality selection is v1.3 scope. |
| Hard constraint encoding (exclusion vs corridor vs route) | Partial | Deterministic planner sets enforcement records but the specific OSM tags in exclusions/corridors still come from LLM. |
| OSM data freshness | Always | Different data fetches may return different POI counts for the same location on different days. This is acceptable and disclosed via dataSnapshotTime. |
| OpenAI seed-based reproducibility | "Mostly deterministic" | OpenAI docs state seed-based reproducibility is not guaranteed. The deterministic planner backend validation is the true source of structural determinism. |

## Safe for client demo?

**YES** — factor table and weights are stable. The Ruby Crossing prompt will produce the same
`student_qsr_cafe` schema every run.

## Safe for client recommendations?

**CONDITIONAL** — the spatial data (OSM POI counts) still varies by fetch time, and the study
area locality enumeration may vary between runs if the LLM picks different place names. Field
validation is always required before acting on any recommendation.
