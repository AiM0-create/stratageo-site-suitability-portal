## Pipeline Audit Table

| Area | Current State (v1.2.0) | Missing Evidence | Risk | v1.3 Fix |
|---|---|---|---|---|
| **Candidate scoring** | `criteria_breakdown` per candidate with score/rawValue/direction | No per-factor raw counts in audit trail; scoring formula not exposed | Client cannot verify how score was computed | `FactorEvidence` + `CandidateEvidence` in EvidenceTrail |
| **Provider query trace** | Notes list mentions merge counts; no machine-readable record | No timestamps, no feature counts, no provider status per query | Cannot verify data freshness or diagnose zero-count layers | `ProviderQueryEvidence` via `QueryTracker` |
| **OSM Overpass fetch** | Single batched union query; total count in fallbacks | No per-tag feature counts; no query timestamp | Cannot audit OSM coverage gaps | `QueryTracker.record_osm()` records count + tags |
| **Google Places fetch** | `data_places.py`, count in notes | No per-type feature counts; no response status | Cannot verify Places API coverage | `QueryTracker.record_places()` records count + types |
| **ORS isochrone fetch** | `fetch_isochrones`, fallback if None | No per-layer isochrone success/failure record | Silent fallback to Euclidean proxy; not in report | `QueryTracker.record_ors()` records mode + n_results |
| **Water/buildability masks** | `mask_stats` dict (corridorRemoved, railwayRemoved, etc.) | Count only; no per-cell or per-feature list | Cannot trace which cells were removed and why | `ExclusionEvidence` records mask type + count + reason |

| **Geometry hash** | None | No stable identifier for the study area polygon | Cannot link two runs to the same geography | `StudyAreaEvidence.geometryHash` (SHA-256 of WKT) |
| **Reproducibility** | `planningFingerprint` (v1.2.0) for planning stability | No snapshot ID; no data-layer fingerprints | Cannot tell if two analyses used the same spatial data | `dataSnapshot.snapshotId` + audit-reproducibility disclaimer |
| **Constraint enforcement** | `constraintEnforcementLevel` advisory/enforced flag | Which specific constraints were enforced and how | Client cannot verify constraint compliance | `ConstraintEvidence` (deferred to v1.3.1; advisory only in v1.3.0) |

---

## Priority Risks Addressed in v1.3.0

1. **Scoring opacity**: Clients asked "why is this site ranked #1?" — no machine-readable breakdown existed. Fixed by `FactorEvidence + CandidateEvidence`.

2. **Data provenance gap**: No record of which providers were queried, when, with what parameters. Fixed by `QueryTracker + ProviderQueryEvidence`.

3. **Exclusion invisibility**: Clients didn't know how many candidate cells were removed by masks. Fixed by `ExclusionEvidence` ledger.

4. **No export**: No way to download the full evidence for external audit. Fixed by `Evidence JSON Export` button + `/evidence.json` endpoint.

5. **Reproducibility ambiguity**: v1.2.0 had `planningFingerprint` for the planning phase, but no `dataSnapshotId` for the execution phase. Fixed by `DataSnapshotEvidence` with honest "audit reproducible" label.

---

## What v1.3.0 Does NOT Fix

- **Full data replay**: Re-running the exact same analysis with the same OSM/Places snapshot is not implemented. Evidence trail is audit-reproducible, not fully replayable.
- **Per-cell OSM feature counts**: The exclusion ledger records batch counts per mask type, not per individual H3 cell.
- **Hard constraint traceability**: Constraint enforcement evidence is minimal in v1.3.0. Full `ConstraintEvidence` schema is deferred to v1.3.1.
- **Historical data diffs**: No comparison between what OSM had at run time vs. today.
