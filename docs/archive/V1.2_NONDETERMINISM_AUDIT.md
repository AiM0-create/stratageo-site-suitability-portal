# v1.2 Non-Determinism Audit

**Date:** 2026-06-24
**Branch:** feature/v1.2.0-deterministic-planning

---

## Problem

The same prompt submitted in two separate sessions produced materially different internal setups:
- Different factor keys and weights
- Different candidate universes
- Different recommendation statuses
- Same prompt once recommended Ruby Park, once returned "no reliable recommendation" with Kushtia excluded

---

## Source-by-Source Analysis

| Area | Current behaviour | Non-determinism risk | Fix planned |
|---|---|---|---|
| **LLM factor selection** | gpt-5.4-mini freely invents factor keys and names each run | HIGH — same archetype, different factor list | Canonical schema locked in `canonical_archetypes.py`; LLM may not add/remove factors |
| **LLM weight assignment** | P3 says "derived from business logic" but LLM chooses freely | HIGH — 32/27/18 one run, 33/25/17 another | Weights frozen in canonical schema; LLM may not modify |
| **LLM catchment radii** | Not constrained; LLM varies walk minutes | MEDIUM — 8 vs 10 min walk changes candidate count | Canonical schema specifies catchment; LLM may not modify |
| **Archetype selection** | intent_parser returns key; LLM may override in plan | MEDIUM — "student cafe" vs "qsr" different factor structures | Deterministic planner enforces parser's archetype key |
| **studyArea.places list** | LLM enumerates localities; different runs pick different subsets | HIGH — Kolkata "Ruby Crossing" area vs "EM Bypass" area | Canonical study-area resolution from place names; normalized |
| **Hard constraint encoding** | LLM decides whether "near Ruby Crossing" is exclusion/corridor/routeConstraint | HIGH — changes which hexes are masked | Constraint types locked by deterministic planner per archetype |
| **temperature=0.2** | Not 0; small probability mass on non-greedy tokens | MEDIUM — structural field values can vary | Set temperature=0 for spec-building; use seed where available |
| **topN** | RawIntent parser enforces it, but LLM may override output.topN | LOW — RawIntent already enforced post-LLM | Confirmed: `resolved_top_n` written to spec after LLM |
| **Recommendation mode** | Critic and viability gate set it, but LLM mentions it in reply | LOW-MEDIUM — no functional effect but confusing | LLM may not set recommendationMode; engine sets it only |
| **Competition scoring** | inverted-U curve vs simple negative — LLM decides | MEDIUM — can flip result | Canonical schema specifies curve type |
| **Study area geometry** | LLM varies hull buffer and places list | HIGH — different hexes screened | Deterministic normalization of place names |
| **siteClaimLevel** | LLM sets it; sometimes "micro_market_zone", sometimes "point_candidate" | MEDIUM | Canonical schema enforces `micro_market_zone` for all non-parcel archetypes |
| **planningMode / weightsSource** | Not tracked | N/A | Add to SpecV2; set by planner |
| **Spec fingerprint** | Not computed | N/A | Add `specFingerprint` and `planningFingerprint` |

---

## Root cause summary

The LLM consultant currently acts as **both the methodology designer and the result interpreter**. For determinism, it should only be the **interpreter** — it explains and summarizes a methodology that the deterministic planner has already fixed.

---

## Fix architecture

```
Prompt
  → RawIntent parser (deterministic)
  → Archetype selection (deterministic)
  → Canonical schema lookup (deterministic)
  → LLM (explanation + study area + clarification only)
  → Deterministic planner override (structural fields)
  → SpecV2 validation
  → Engine execution (already deterministic given same data)
```
